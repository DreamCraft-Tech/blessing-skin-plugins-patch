# 网页登录与 Yggdrasil 登录记录 1.1.1

## 运行环境与安装

适用 Blessing Skin Server 6.0.2 开发快照、Laravel 10、PHP 8.5、MariaDB。运行包包含插件代码与 Twig 模板。

1. 在插件管理上传 `login-history_1.1.1_php85.zip` 并启用。手动部署时将 `login-history/` 放入网站插件目录。
2. 更新时覆盖原目录并重新启用插件。数据库账号需具备插件表、字段和索引的创建权限。
3. 用户入口为“高级功能 → 登录记录”；后台“插件配置 → 网页登录与 Yggdrasil 登录记录”显示功能及既有日志接入状态。

OpenResty 使用网站现有 Laravel 路由规则，运行目录为 `public/`。OPcache 关闭时间戳检查时，更新后重启 PHP 运行环境。

## 采集事件

| 来源 | 事件 |
| --- | --- |
| 网页 | Laravel `Login` 成功事件 |
| Yggdrasil | `authenticate` 认证成功 |
| Yggdrasil | `refresh` 刷新令牌或选择角色成功 |
| Yggdrasil | `join` 加入服务器请求成功 |

支持 yggdrasil-api 5.2.1 与 yggdrasil-connect 6.2.0。采集从插件启用时开始，网页登录通过实际控制器和 OAuth 驱动识别密码、企业微信、GitHub、Google、Microsoft Live、LittleSkin 等渠道；自动恢复会话使用独立渠道标签。既有记录沿用原渠道数据。

记录字段包括时间、用户 UID、来源、操作、渠道、IP、User-Agent，以及角色 ID、名称和 UUID 快照。采集逻辑使用成功响应与受信任的登录事件上下文。

## 多角色数据

每条记录归属认证时的用户 UID。角色快照分为实际选择角色与当时可用角色：

- `authenticate` 根据响应中的 `selectedProfile` 保存实际选择角色，并保存可用角色列表。
- `refresh` 保存本次响应选定的角色。
- `join` 根据已验证的 UUID 关联角色并保存名称快照。
- 账号级认证对应“未选择角色”筛选项，具体角色筛选匹配实际选择角色。

角色改名、转移和删除后，历史快照及原 UID 归属保持稳定。每次最多保存 1000 项角色快照，优先保存实际选定角色。`join` 记录表示认证服务接受了加入服务器请求。

## 用户查询

支持按来源、操作、渠道、角色和日期筛选，每页 20 条。查询范围按当前登录用户 UID 确定。

客户端列根据 User-Agent 显示 Windows、macOS、Linux、iOS、Android、iPadOS，以及企业微信、微信等客户端。鼠标悬停或键盘聚焦可查看保存的完整 User-Agent；字段存储上限为 512 字符。模板通过 Twig 自动转义输出。

新记录按 UTC 保存，查询日期和页面时间采用网站时区。记录保留 90 天，产生记录时最多每小时清理一次过期数据。

## 数据库与历史日志

插件使用网站数据库表前缀，建立两张 InnoDB 表：

- `login_history_entries`：用户、时间、来源、操作、渠道、IP 和客户端信息。
- `login_history_profiles`：关联记录的实际选择角色与可用角色快照。

启用时补齐表、字段及索引，包括 `login_channel`。角色快照通过插件内部外键关联记录；用户归属由应用层 UID 管理，账号删除事件清理对应记录。插件停用、卸载时保留历史表。

检测到既有 Yggdrasil 日志表后，页面提供历史来源选项，读取时间、操作、IP 和角色编号。既有日志时间采用网站时区，生命周期由原日志插件管理。

## 验证

验证环境为 PHP 8.5.12、Laravel 10.48.25 和 SQLite 测试数据库。测试覆盖标准网页登录事件、第三方渠道识别、Yggdrasil 成功响应、多角色快照、用户归属、筛选、时区、保留期和客户端显示。验证包包含测试日志、JUnit 结果及语法检查记录。
