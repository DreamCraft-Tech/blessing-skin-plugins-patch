# 企业微信登录与绑定

适用于此前构建的 **Blessing Skin Server 6.0.2 开发快照 / Laravel 10 / PHP 8.5 / MariaDB**。不依赖 OAuth 核心插件，不需要额外安装 Composer 包或编译前端资源。

## 功能

- 登录页面提供企业微信扫码入口，跳转到企业微信官方二维码页面。
- 已有账号登录皮肤站后，可在个人中心的“企业微信绑定”菜单自行扫码绑定。
- 绑定后，企业微信扫码登录对应的已有账号。
- 用户验证当前皮肤站密码后自行解绑；不更改或删除原账号。
- 一个企业微信成员只能绑定一个皮肤站账号，一个皮肤站账号只能保留一项绑定。
- 不自动注册，不读取邮箱、手机号进行账号匹配或合并。
- 拒绝外部联系人、无法读取的应用范围外成员、已停用或未激活成员，以及被封禁的皮肤站账号。

## 安装到 1Panel

1. 在 Blessing Skin 后台上传 `wecom-login_1.0.0_php85.zip` 并启用。插件会创建 `wecom_bindings` 和 `wecom_oauth_states` 两张表；会自动使用网站配置的数据库表前缀。两张插件表使用 InnoDB；网站原有 users 表也需要支持外键（MariaDB / MySQL 使用 InnoDB）。初次启用需要数据库账号具备建表和创建外键的权限。
2. 在**网站项目根目录**的 `.env` 中加入以下配置，不要修改 `public/` 下的文件：

```dotenv
WECOM_CORP_ID=你的企业ID
WECOM_AGENT_ID=你的自建应用AgentID
WECOM_SECRET=你的自建应用Secret
WECOM_REDIRECT_URI=https://你的皮肤站域名/auth/wecom/callback
```

3. 在 1Panel 网站实际绑定的 **PHP 8.5 运行环境**中，进入项目根目录执行：

```sh
php artisan config:clear
```

本插件在启动时读取 `.env`，请保持配置缓存关闭；如果你必须使用 `config:cache`，需把四项 `WECOM_*` 注入 PHP-FPM 的真实进程环境，而不是仅保存在 `.env`。

4. 打开后台插件的“配置”页面，确认 CorpID、AgentID、完整回调 URL，以及“Secret 已设置”状态。前三项可在后台保存，后台设置优先于 `.env`；Secret 仅从环境配置读取，不在网页显示。
5. 按下一节配置企业微信自建应用，再用一个测试账号完成绑定与扫码登录。

可以手动解压 ZIP，把 `wecom-login/` 放进网站的 `plugins/`（或实际 `PLUGINS_DIR`）。更新旧版本时替换插件代码目录；数据库中的绑定不会因替换代码丢失。

### OpenResty

沿用此前提供的伪静态规则，运行目录仍指向网站 `public/`，不需要为本插件另加规则。`/auth/wecom/callback` 的查询参数必须保留。域名归属校验如要求放置 `WW_verify_*.txt`，应将该官方校验文件放到网站 `public/` 根目录。

## 企业微信管理后台

使用**企业内部自建应用**，不是个人微信登录、外部联系人登录或第三方服务商应用。

- CorpID：企业信息中的企业 ID。
- AgentID：自建应用的应用 ID。
- Secret：此自建应用的 Secret，不是通讯录 Secret，也不是回调 Token / EncodingAESKey。
- 启用应用相应的企业微信 Web 登录能力，设置授权回调域名为皮肤站域名；插件中的回调 URL 为 `https://皮肤站域名/auth/wecom/callback`，不带额外查询参数。
- 配置应用可见范围；该应用的凭据必须能通过“读取成员”接口访问扫码成员。插件会再次检查成员可访问状态，读取失败时拒绝登录或绑定。
- 按企业微信后台要求配置可信域名、域名归属校验及服务器可信 IP。可信 IP 使用服务器对外请求企业微信接口时的出口公网 IP。
- 网站必须使用 HTTPS，并保持浏览器能正常保存网站会话 Cookie；若使用反向代理，确保站点能正确识别 HTTPS。

企业微信管理后台不同版本的菜单名称可能不同，以你企业当前可用的自建应用 Web 登录配置为准。

## 用户使用流程

### 首次绑定

1. 使用现有邮箱、密码或既有登录方式登录皮肤站。
2. 点击个人中心菜单“企业微信绑定”。
3. 确认当前登录的是想要绑定的皮肤站账号，点击“扫码绑定企业微信”。
4. 用企业微信扫码并确认授权。成功后返回绑定页面，显示成员姓名、成员账号和企业 ID。

### 后续登录

在皮肤站登录页面点击“企业微信扫码登录”，扫码确认后登录已经绑定的皮肤站账号。未绑定成员会收到提示，需要先使用原有方式登录再绑定；不会创建新账号。

### 解绑与换绑

在“企业微信绑定”页面输入当前**皮肤站密码**，验证后解除绑定。更换成员时先解绑再重新扫码。

没有本地密码的第三方登录账号，需要先在皮肤站个人资料中设置密码才能解绑。忘记密码时先走网站现有的密码找回流程。插件不会改变已存在的其他登录方式。

## 数据与安全行为

- 绑定以“企业 ID + 成员账号”生成身份摘要，并有成员身份唯一索引、用户唯一索引；不会按姓名、邮箱合并账号。
- 授权状态使用 32 字节随机数，数据库仅存摘要，绑定原浏览器会话、当前账号、操作类型和应用配置，5 分钟过期。数据库事务及行锁保证状态仅消费一次；重新发起授权会取消同一浏览器之前的尝试。
- 用户绑定、解绑、后台保存配置使用 POST 和网站原有 CSRF 防护；解绑额外验证本地密码，并限制请求频率。
- 登录后轮换会话 ID，拒绝封禁或被删除的绑定账号。登录过程触发网站原有 `auth.login.ready`、`auth.login.succeeded` 和 `UserLoggedIn` 事件。
- 企业微信 access token 仅由后端获取，缓存前使用网站 APP_KEY 加密。密钥和 token 不发给浏览器，HTTP 失败信息不透传包含凭据的 URL。
- 企业微信请求固定为官方 HTTPS 域名，禁止跟随 HTTP 重定向；token 失效时最多刷新一次。
- 回调和账号操作响应禁止缓存，设置不发送 Referer；页面动态内容默认 HTML 转义。
- 数据库支持表前缀。用户从网站删除时，绑定通过外键一并删除。
- 停用或删除插件**保留**已有绑定表，便于恢复和回滚，不自动清空账号关联数据。

修改 CorpID / AgentID / Secret / 回调 URL 会使正在进行的授权失效，用户需重新扫码。改换企业后，旧企业成员不能再通过旧绑定登录；用户可通过原登录方式进入账号后解绑。

## 已完成验证

在此前的 Blessing Skin 构建和 PHP 8.5.12 下执行了 **48 项测试、333 个断言，全部通过**，测试记录随交付的验证包提供。测试使用 SQLite 内存数据库与模拟的企业微信 HTTP 响应，覆盖页面、绑定、登录、解绑、配置权限、CSRF、授权状态重放、跨会话/跨账号、成员范围检查、token 缓存刷新及失败脱敏。

**尚未使用你的企业微信真实凭据进行扫码联调，也未连接你的 MariaDB 实例。** 需要你配置自建应用后，分别用一个已有账号和一个未绑定成员验证实际绑定、登录、解绑；生产使用前也应确认数据库建表和外键权限。

这不是服务商多企业应用，也不支持外部联系人、个人微信登录或自动开通皮肤站账号。应用级可用范围和访问规则依赖企业微信管理后台配置。

## 运行测试

测试需要 Blessing Skin Server 的源码、开发依赖，以及其 `.env.testing`；不应在生产目录或真实数据库上执行测试。

```sh
BLESSING_SERVER_PATH=/path/to/blessing-skin-server \
/path/to/php-8.5 /path/to/blessing-skin-server/vendor/bin/phpunit \
  -c /path/to/wecom-login/phpunit.xml
```

源码中包含全部测试；可部署 ZIP 不含测试文件，无需在服务器安装 PHPUnit。

## 接口参考

- 扫码页面：`https://open.work.weixin.qq.com/wwopen/sso/qrConnect`

- 通过授权 code 获取身份：`https://qyapi.weixin.qq.com/cgi-bin/auth/getuserinfo`
- 检查成员可访问状态：`https://qyapi.weixin.qq.com/cgi-bin/user/get`

不保存、也不使用成员手机号、邮箱或敏感信息 user_ticket。
