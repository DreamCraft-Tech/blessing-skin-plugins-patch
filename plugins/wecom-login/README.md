适用于此前构建的 **Blessing Skin Server 6.0.2 开发快照 / Laravel 10 / PHP 8.5 / MariaDB**。不依赖 OAuth 核心插件，不需要额外安装 Composer 包或编译前端资源。

## 功能

- 登录页面提供企业微信扫码入口，跳转到企业微信官方二维码页面。
- 已有账号登录皮肤站后，可在用户首页的“企业微信账号”卡片或“高级功能 → 企业微信绑定”菜单自行扫码绑定。
- 绑定后，企业微信扫码登录对应的已有账号。
- 用户验证当前皮肤站密码后自行解绑；不更改或删除原账号。
- 一个企业微信成员只能绑定一个皮肤站账号，一个皮肤站账号只能保留一项绑定。
- 不自动注册，不读取邮箱、手机号进行账号匹配或合并。
- 拒绝外部联系人、无法读取的应用范围外成员、已停用或未激活成员，以及被封禁的皮肤站账号。

## 安装到 1Panel

1. 在 Blessing Skin 后台上传 `wecom-login_1.2.0_php85.zip` 并启用。插件会创建 `wecom_bindings` 和 `wecom_oauth_states` 两张表；会自动使用网站配置的数据库表前缀。两张插件表使用 InnoDB，不对宿主 users 表建立外键。初次启用需要数据库账号具备建表权限。
2. 推荐直接打开后台“插件配置 → 企业微信登录与绑定”，填写企业 ID、应用 ID、完整回调 URL 和应用 Secret 并保存。也可在**网站项目根目录**的 `.env` 中配置以下备用值，不要修改 `public/` 下的文件：

```dotenv
WECOM_CORP_ID=你的企业ID
WECOM_AGENT_ID=你的自建应用AgentID
WECOM_SECRET=你的自建应用Secret
WECOM_REDIRECT_URI=https://你的皮肤站域名/auth/wecom/callback
```

3. 如果使用 `.env` 配置，在 1Panel 网站实际绑定的 **PHP 8.5 运行环境**中，进入项目根目录执行：

```sh
php artisan config:clear
```

使用 `.env` 时请保持配置缓存关闭；如需 `config:cache`，将 `WECOM_*` 注入 PHP-FPM 的真实进程环境。全部凭据由后台保存时不依赖 `.env`，无需为此关闭配置缓存。

4. 打开后台插件的“配置”页面，确认 CorpID、AgentID、完整回调 URL，以及“Secret 已设置”状态。四项均可在后台保存，后台设置优先于 `.env`。Secret 加密存储，不回显；输入框留空保留旧值。要恢复环境变量 Secret，勾选相应选项且不要填写新 Secret。保存后无需重启 PHP。请保留网站 APP_KEY；更换 APP_KEY 后需重新填写 Secret。
5. 按下一节配置企业微信自建应用，再用一个测试账号完成绑定与扫码登录。

可以手动解压 ZIP，把 `wecom-login/` 放进网站的 `plugins/`（或实际 `PLUGINS_DIR`）。更新旧版本时替换插件代码目录；数据库中的绑定不会因替换代码丢失。

### OpenResty

沿用此前提供的伪静态规则，运行目录仍指向网站 `public/`，不需要为本插件另加规则。`/auth/wecom/callback` 的查询参数必须保留。域名归属校验如要求放置 `WW_verify_*.txt`，应将该官方校验文件放到网站 `public/` 根目录。

如安装了“隐藏高级功能”插件，它会按自身规则隐藏整个分组；需要在侧栏显示企业微信二级菜单时，请停用该隐藏插件。首页绑定卡片和绑定页面仍可使用。

## 企业微信管理后台

使用**企业内部自建应用**，不是个人微信登录、外部联系人登录或第三方服务商应用。

- CorpID：企业信息中的企业 ID。
- AgentID：自建应用的应用 ID。
- Secret：此自建应用的 Secret，不是通讯录 Secret，也不是回调 Token / EncodingAESKey。
- 启用应用相应的企业微信 Web 登录能力，设置授权回调域名为皮肤站域名；插件中的回调 URL 为 `https://皮肤站域名/auth/wecom/callback`，不带额外查询参数。
- 配置应用可见范围；该应用的凭据必须能通过“读取成员”接口访问扫码成员。插件会再次检查成员可访问状态，读取失败时拒绝登录或绑定。
- 按企业微信后台要求配置可信域名、域名归属校验及服务器可信 IP。可信 IP 使用服务器对外请求企业微信接口时的出口公网 IP。
- 网站必须使用 HTTPS，并保持浏览器能正常保存网站会话 Cookie；若使用反向代理，确保站点能正确识别 HTTPS。

企业微信管理后台不同版本的菜单名称可能不同，以你企业当前可用的自建应用 Web 登录配置为准。

## 用户使用流程

### 首次绑定

1. 使用现有邮箱、密码或既有登录方式登录皮肤站。
2. 展开个人中心“高级功能”，点击“企业微信绑定”（与“OAuth 应用”并列）。
3. 确认当前登录的是想要绑定的皮肤站账号，点击“扫码绑定企业微信”。
4. 用企业微信扫码并确认授权。成功后返回绑定页面，显示成员姓名、成员账号和企业 ID。

### 后续登录

在皮肤站登录页面点击“企业微信扫码登录”，扫码确认后登录已经绑定的皮肤站账号。未绑定成员会收到提示，需要先使用原有方式登录再绑定；不会创建新账号。

### 解绑与换绑

在“高级功能 → 企业微信绑定”页面输入当前**皮肤站密码**，验证后解除绑定。更换成员时先解绑再重新扫码。

没有本地密码的第三方登录账号，需要先在皮肤站个人资料中设置密码才能解绑。忘记密码时先走网站现有的密码找回流程。插件不会改变已存在的其他登录方式。

## 数据与安全行为

- 绑定以“企业 ID + 成员账号”生成身份摘要，并有成员身份唯一索引、用户唯一索引；不会按姓名、邮箱合并账号。
- 授权状态使用 32 字节随机数，数据库仅存摘要，绑定原浏览器会话、当前账号、操作类型和应用配置，5 分钟过期。数据库事务及行锁保证状态仅消费一次；重新发起授权会取消同一浏览器之前的尝试。
- 用户绑定、解绑、后台保存配置使用 POST 和网站原有 CSRF 防护；解绑额外验证本地密码，并限制请求频率。
- 登录后轮换会话 ID，拒绝封禁或被删除的绑定账号。登录过程触发网站原有 `auth.login.ready`、`auth.login.succeeded` 和 `UserLoggedIn` 事件。
- 企业微信 access token 仅由后端获取，缓存前使用网站 APP_KEY 加密。已保存的密钥和 token 不返回给浏览器，HTTP 失败信息不透传包含凭据的 URL。管理员首次填写 Secret 的提交请求仍需通过 HTTPS 发送。
- 企业微信请求固定为官方 HTTPS 域名，禁止跟随 HTTP 重定向；token 失效时最多刷新一次。
- 回调和账号操作响应禁止缓存，设置不发送 Referer；页面动态内容默认 HTML 转义。
- 数据库支持表前缀。插件启用期间，用户通过网站模型删除时，由删除事件清理绑定及授权状态。
- 停用或删除插件**保留**已有绑定表，便于恢复和回滚，不自动清空账号关联数据。

修改 CorpID / AgentID / Secret / 回调 URL 会使正在进行的授权失效，用户需重新扫码。改换企业后，旧企业成员不能再通过旧绑定登录；用户可通过原登录方式进入账号后解绑。

## 缺表修复版本 1.1.1

启用回调和每次插件启动均检查两张插件表，缺哪张补哪张，不删除已有表或记录。已启用站点覆盖升级后刷新页面即可补建；无需反复点击启用。数据库账号仍须具备 CREATE、INDEX 权限（登录记录插件还需插件表之间的 REFERENCES 权限）。若补建失败，请查看网站日志中的首个建表异常（例如外键、表引擎或权限），不要只依据后续的“表不存在”错误判断。

此修复版不创建指向宿主 users.uid 的外键，避免 MariaDB errno 150。账号通过网站正常删除时，由用户模型删除事件清理关联插件数据；插件停用时或绕过模型直接执行 SQL 删除账号，不触发此清理。插件自己的两张登录记录表之间仍使用外键级联。

已核对当前主系统安装迁移：users.uid 使用 increments，即 MariaDB INT UNSIGNED 自增主键；原插件 user_id 同为 unsignedInteger，源码定义的位数与符号一致。主系统 database.php 的 engine 为 null，建 users 表时也没有强制指定引擎。因此 errno 150 的实际原因需通过 SHOW CREATE TABLE users 和 SHOW TABLE STATUS 确认，不能仅凭异常认定为字段类型不一致。

已根据现场 SHOW CREATE TABLE 确认 users 使用 MyISAM，插件表使用 InnoDB，导致跨引擎外键创建失败。新版本取消该外键，并补建缺失索引（包含企业微信绑定唯一约束和授权状态唯一约束）；不会清空已有数据。若已有重复绑定导致唯一索引无法建立，会明确报错，不自动删除或合并绑定。

## 1.1.2 接口诊断日志

企业微信接口错误记录到网站 Laravel 日志，默认 storage/logs/laravel-YYYY-MM-DD.log；LOG_CHANNEL=single 时为 laravel.log。搜索 wecom-login。仅记录接口名、HTTP 状态和数字 errcode，不记录 errmsg 原文、Secret、access_token、授权 code、成员个人资料、完整 URL 或异常堆栈。transport_or_invalid_response 表示网络、TLS、非成功 HTTP 状态或无效响应；api_error 对应企业微信返回的非零 errcode。errcode=0 的本地拒绝使用单独原因标记。

默认 LOG_CHANNEL=daily、LOG_LEVEL=debug 可接收 warning 诊断。若设置为 error/critical 则应临时调整为 warning 并在网站 PHP 环境执行 php artisan config:clear。无需打开 APP_DEBUG。扫码页面本身在跳回本站前失败时，服务器尚未收到回调，因此不会产生插件 API 日志。

## 1.2.0 可选登录消息推送

1. 管理员在「插件配置 → 企业微信登录与绑定」勾选「允许发送网页登录通知」，保存配置。默认关闭。
2. 已绑定用户在「高级功能 → 企业微信绑定」勾选「接收企业微信登录通知」，保存偏好。默认关闭，升级不会自动订阅已有用户。
3. 用户下一次主动网页登录成功时，使用当前自建应用的 `POST /cgi-bin/message/send` 向该绑定成员发送文本消息；原生密码登录（含勾选记住我）、本插件扫码登录，以及触发标准 Laravel web Login 事件的其他登录方式适用。自动通过记住我恢复会话不推送；绑定动作、失败登录、Yggdrasil 游戏认证不推送。

内容包含站点名、皮肤站 UID、登录时间及网站时区偏移、IP、设备 User-Agent 和登录方式，不显示企业 ID，不包含密码、Secret、令牌或授权码。IP 采用网站 Laravel 配置的可信代理规则。

推送使用已有 CorpID / AgentID / Secret，无需机器人 Webhook。成员须能接收当前自建应用消息，应用接口服务器可信 IP 及凭据仍需正确配置。仅向当前绑定的单个成员发送，禁止 @all 及多成员分隔符。

升级自动为 wecom_bindings 补加 notify_login 布尔列，保留原绑定与数据，需要 ALTER 权限。解除绑定后偏好随绑定删除，再次绑定默认关闭。后台总开关关闭时用户偏好保留，但不会发消息。

实现面向当前 PHP-FPM 部署，在 HTTP 响应结束后的应用终止回调中尽力发送，无需额外队列进程。发送异常不会使登录失败，写入 wecom-login 诊断日志；令牌明确过期时自动更新并重试一次，网络超时等情况不重复发送。不提供持久队列、失败补发或送达保证；响应后的进程中止也可能导致消息丢失。投递前会再次检查开关、绑定及用户状态，避免解绑、换绑后仍投递旧通知。

已用 HTTP 模拟测试消息结构、开关与用户隔离、重复事件去重、令牌刷新、失败不影响登录及禁止广播；尚未调用你的企业微信应用做真实推送联调。
