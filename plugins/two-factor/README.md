# 两步验证 1.0.0

适用 Blessing Skin Server 6.0.2 至 6.0.6_patch、Laravel 10、PHP 8.5、MariaDB。运行包包含插件代码、前端资源、WebAuthn 验证库及二维码生成依赖。

## 安装

1. 在插件管理上传 `two-factor_1.0.0_php85.zip` 并启用；手动安装时将压缩包中的 `two-factor/` 放入项目 `plugins/`。
2. 在“插件配置 → 两步验证”中设置站点 HTTPS 地址及显示名称，再保存策略。站点地址例如 `https://skin.example.com`，RP ID 为该地址的主机名。超级管理员可修改配置，管理员可查看。
3. 用户菜单新增“两步验证”，与“个人资料”平级。页面分别管理 TOTP 与通行密钥设备。

插件启用及启动时初始化三个 InnoDB 数据表：`two_factor_accounts`、`two_factor_totp`、`two_factor_passkeys`。表内 user_id 对应主系统 users.uid，类型为 INT UNSIGNED。数据库账号需具备创建表和索引的权限。

PHP 运行环境使用 OpenSSL、mbstring、DOM / XML；浏览器通过 HTTPS 使用 WebAuthn，localhost 支持 HTTP 开发调试。站点 APP_KEY 用于加密 TOTP 密钥，备份与迁移时保留同一 APP_KEY。服务器时间应通过 NTP 同步。

## 用户操作

- 添加设备前确认身份；近期完成登录或两步验证后，可在配置的有效期内管理设备。
- 添加 TOTP：填写设备名称，使用验证器扫描站内二维码或输入手动密钥，输入当前六位验证码确认。
- 添加通行密钥：填写设备名称，调用浏览器或系统的通行密钥注册界面，使用设备解锁完成注册。
- 密码或第三方网页登录成功后，已开启两步验证的用户继续输入 TOTP、使用通行密钥，或使用一次性恢复码完成登录。
- 登录页的通行密钥入口与 OAuth、企业微信入口共用一个登录方式区域；直接登录使用可发现凭据并要求设备身份验证。
- 每次恢复码生成 10 组，每组可使用一次。首次添加设备后显示恢复码；重新生成后替换原恢复码。
- 设备可重命名、移除。移除设备和重新生成恢复码使用系统确认弹窗。站点强制策略下，移除最后一个设备前需添加另一设备。

## 后台策略

配置页使用两列卡片，包含用户策略、验证码及身份确认、通行密钥与站点身份。

| 配置 | 默认值 / 范围 |
| --- | --- |
| 两步验证范围 | 用户自行开启；可选管理员必须开启、所有用户必须开启 |
| 允许新增 TOTP / 通行密钥 | 分别开启；开关控制新增设备 |
| 通行密钥直接登录 | 开启；可单独关闭 |
| 设备身份验证 | 默认 required；可选 preferred，直接登录始终 required |
| 验证器类型 | 所有设备；可选平台验证器、跨设备 / 外置安全密钥 |
| TOTP 设备数量 | 默认 5，范围 1–10 |
| 通行密钥数量 | 默认 10，范围 1–50 |
| TOTP 时间容差 | 前后各 30 秒；可设为仅当前时间段 |
| 浏览器等待时间 | 默认 60 秒，范围 15–120 |
| 服务端 WebAuthn 请求有效期 | 默认 120 秒，范围 60–300 |
| 设备管理身份确认有效期 | 默认 300 秒，范围 60–600 |

强制策略下，尚未设置设备的用户登录后进入设置页。已有通行密钥与 RP 域名关联；域名迁移需安排设备重新注册。

## 接入方式

插件通过扩展 Laravel web SessionGuard 在建立登录会话之前执行第二步验证，兼容主系统密码登录及通过 web guard 登录的 OAuth / 企业微信插件。原 SessionGuard 的会话字段和记住我 Cookie 名称保持一致。记住我恢复会话时，已开启两步验证的账号进入第二步验证。已有受保护会话按账号与策略版本重新确认。

完成第二步后触发一次 Laravel Login 及主系统登录成功事件；与 login-history 配合时保留密码、企业微信或 OAuth 渠道，通行密钥直接登录记录为 `custom:passkey`。Yggdrasil 游戏认证及 OAuth Bearer API 沿用各自认证协议；本插件负责网页会话认证。

TOTP 使用 RFC 6238 SHA-1、30 秒周期、6 位数字，并保存各设备已接受的时间步。WebAuthn 使用服务端随机挑战、严格 Origin / RP ID 校验、一次性会话状态和凭据归属校验。直接登录要求 UV 和匹配的 userHandle。恢复码在数据库中保存哈希。敏感页面使用 no-store 响应，管理操作使用 CSRF 校验与分接口限流。

WebAuthn 验证使用 lbuchs/webauthn 2.2.0；二维码使用 bacon/bacon-qr-code 3.1.1。本插件包含独立 Composer 自动加载器后缀 BlessingTwoFactor。

## 设备恢复与维护

站点运维人员可在项目根目录、网站 PHP 运行环境执行：

```sh
php artisan two-factor:reset 123
```

将 123 替换为目标 UID。命令清除该用户的验证设备与恢复码、更新账号保护版本及记住我令牌；用户重新登录后按站点策略添加设备。

更新插件时覆盖整个 `plugins/two-factor/`，包括 `vendor/`，重新启用插件，并重启 PHP 运行环境刷新 OPcache。数据备份包含上述三张表及站点 APP_KEY。
